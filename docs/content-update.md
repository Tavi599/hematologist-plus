# Як оновити вміст довідника

Сайт читає базу, але **не пише в неї**. Усе, що бачить лікар — препарати, фасування, параметри
розведення, схеми, хвороби — лежить у теці [`data/`](../data) цього репозиторію, а в базу
потрапляє окремим кроком. Тож оновлення завжди йде в одному напрямку:

```
data/*.json  →  перевірка  →  коміт у GitHub  →  деплой сайту  →  SQL у Supabase
```

Порядок важливий: **спершу код, потім база**. Копія програми, встановлена на телефоні, працює зі
старим кодом, доки її власник не погодиться оновитись, і вона має пережити нову колонку.

---

## 1. Змінити файл у `data/`

Формат, обов'язкові поля й те, що з чим пов'язано: [data-format.md](data-format.md).

Кілька правил, яких варто триматись:

- **Жодного вигаданого числа.** Доза, максимальна доза, розведення, швидкість — лише з джерела,
  і джерело записується поруч (`sources`: назва, посилання, версія протоколу, дата звірки).
  Якщо значення немає — краще лишити порожнім: програма прямо скаже, що параметрів немає.
- Якщо протокол дає **діапазон** («1–2 години»), береться повільніший край, а діапазон
  записується в `notes` — щоб потім було видно, звідки взялось число.
- **Реєстрові ознаки** (Нацперелік, ДЕЦ, керований доступ) у довідник не вносяться.
- **Даних пацієнтів у `data/` не буває.** Ніколи, в жодному коментарі.

## 2. Перевірити

```bash
npm run data:validate
```

Перевіряє схему кожного файлу, посилання між сутностями (схема → препарат → фасування) і показує
прогалини, через які курс не порахується. Поки тут помилка — далі йти не треба.

## 3. Закомітити й дочекатись деплою

```bash
git add data
git commit -m "..."
git push
```

GitHub Actions збирає сайт і публікує його на Pages. **Дочекайтесь зеленого запуску**: червона
збірка означає, що сайт і далі віддає попередню версію — а база вже матиме нові дані.

## 4. Залити в Supabase

Секретного ключа ні в репозиторії, ні в браузері немає — і не повинно бути. Тому зміни
заливаються через SQL Editor:

```bash
npm run data:sync                                  # суха перевірка: що саме зміниться
npm run data:sync -- --sql C:\шлях\sync.sql        # один файл, одна транзакція
```

Далі:

1. Відкрити проєкт `hematologist-plus` у Supabase → **SQL Editor**.
2. Вставити вміст файлу. **Не через `clip.exe`** — він псує кирилицю, і в базу потрапить
   «кракозябра». У PowerShell:
   ```powershell
   Set-Clipboard -Value ([System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8))
   ```
3. Перед запуском поглянути очима: чи читається українська, чи ті таблиці згадані.
4. Виконати.
5. Перевірити: `npm run data:sync` має показати 0 змін.

Прапорець `--prune` додатково **видаляє** з бази рядки, яких більше немає у `data/`. Без нього
старий запис просто лишається. Видалення незворотне — спершу подивіться суху перевірку.

## Що робити, коли проєкт Supabase «зник»

Безкоштовний проєкт засинає після тижня без запитів; тоді його адреса перестає навіть
відкриватись, і сайт показує лише збережену офлайн-копію. Лікується в кабінеті Supabase кнопкою
**Restore / Resume project**. Щоб це траплялось рідше, працює
[`supabase-keep-alive.yml`](../.github/workflows/supabase-keep-alive.yml) — раз на три дні
звертається до бази.

## Якщо на телефоні лишилась зовсім стара версія

Коли довідник не завантажується, сайт показує попередження з кнопкою «перевстановити програму»
(та сама кнопка з'являється на екрані помилки): вона скидає офлайн-копію довідника, знімає
службовий робітник і перезавантажує сторінку.
